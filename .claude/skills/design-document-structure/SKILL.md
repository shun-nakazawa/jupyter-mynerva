# 設計ドキュメント構造

設計ドキュメント作成時に以下の構造に従う。

## 推奨構造

1. **機能概要** — 主要機能の箇条書き
2. **詳細仕様** — トリガー、設定、挙動
3. **システムフロー** — mermaid シーケンス図で可視化
4. **セキュリティ設計** — 脅威と対策のテーブル、フェイルセーフ設計、技術的制約
5. **データ構造** — API リクエスト/レスポンスのフォーマット
6. **関数呼び出し構造** — 主要関数の関係、関数一覧
7. **制約事項** — スコープ、既知の制限
8. **テスト観点** — 機能テスト、セキュリティテスト、エッジケース
9. **参考資料** — 関連ドキュメントへのリンク
10. **付録: 却下した実装方針** — 代替案とその理由（将来の参考用）

## 原則

- **TL;DR ファースト**: 複数の方針がある場合、比較表・選定基準・確認事項を冒頭に記載
- **簡潔な記述**: 冗長さを避け、本質に集中
- **コード例は不要**: データ構造のフォーマット説明のみ
- **却下した方針も付録に残す**: 繰り返し議論を防ぐ
- **技術的制約を明記**: できないことを明確にする
- **mermaid 図でフロー可視化**: シーケンス図やフローチャートを活用
